# 設計書への補足（設計の確認で決めた変更）

`docs/DESIGN_SPEC.md` と食い違う場合は、この補足を優先する。節番号は設計書のもの。

## 変更

1. **LLM提供元（§16, §59）**: `LLM_PROVIDER` の初期値は `ANTHROPIC`。Phase 5 は Anthropic、Phase 8 は OpenAI と Gemini。
2. **書き戻し（§22, §27, §57, ADR 0003）**: Results への書込後すぐには書き戻さない。回答の全問題が確定したときだけフォームへ書き戻す。Queue の `COMPLETED` は「確定して書き戻し済み」、`REVIEW_REQUIRED` は「確認待ち」を表す。
3. **最終点（§26, §31）**: `manual_score` が入っていれば常にそれを最終点とする。`finalizeManualGrades()` は MANUAL と REVIEW_REQUIRED の両方を確定する。
4. **回答の取り込み（§20, §34, §35, ADR 0005）**: フォーム送信トリガーは使わない。1分ごとの定期処理がフォームの新しい回答を拾って Queue に登録する。`submitGrades` 由来の再発火ループは起きない。response_id の一意性は維持する。
5. **ルーブリックの版（§12）**: Questions に版の列は足さない。同じ rubric_id の最大の rubric_version を使い、Results に記録する。
6. **再生成の判定（§18, §28）**: 問題定義のハッシュを Control 側に記録し、前回と同じなら「これでOK」は何もしない。
7. **時間の管理（§22, §24）**: 定期処理は開始から4分で打ち切る。更新から10分以上たった `PROCESSING` は `RETRY` に戻す。
8. **入力形式（§8, §10）**: CONTAINS のキーワードは `correct_answer` に `||` 区切り。CHECKBOX の正答も `||` 区切りで、全部合えば満点、それ以外は0点。
9. **個人情報と注入（§11, §39）**:
   - LLMへ送る前に、氏名・メール・学籍番号に当たる欄を除外する純粋関数を通す。
   - 回答は JSON の文字列フィールドで渡し、毎回ランダムな区切りを使う。区切りや指示めいた語を含む回答は REVIEW_REQUIRED にする。
   - Results に回答を書くときは必ず文字列として書く（数式として評価させない）。
   - 未回答は API を呼ばず「未回答」として 0 点で確定する（エラー時の黙った0点とは区別する）。
10. **秘密情報（§41, §42）**: `appsscript.json` の `urlFetchWhitelist` を `https://api.anthropic.com/` に限定する。ログには応答本文を丸ごと出さない。API キーは専用に発行し、提供元側で月額上限を設ける。「GASエディタ直接修正禁止」は運用ルールであり、技術的な強制ではないと README に書く。
11. **フォーム設定（§17）**: 回答後の編集は許可しない。`respondent_email` は `COLLECT_EMAIL=FALSE` のとき空欄。
12. **GAS とテストの両立（§5, §46）**: 純粋ロジックのファイルは末尾に `if (typeof module !== 'undefined') module.exports = {...}` を置く。`.clasp.json` の `rootDir` を `src` にして、`tests/` や `package.json` は GAS に送らない。

13. **記録先の訂正（補足6）**: 問題定義のハッシュ、現在のフォームID、版は Control ではなく Document Properties に保存する（秘密情報ではない）。旧フォームの URL は FormMapping の form_id から辿る。
14. **回答の取り込み（補足4）**: 現在のフォームだけでなく、FormMapping にある全版のフォームから取り込む。閉じた旧版に届いた回答も取りこぼさない。
15. **API 失敗の扱い（§24）**: 提供元の失敗は待ち行列の再試行に任せる。再試行を使い切った最後の試行でだけ REVIEW_REQUIRED にする。止まった PROCESSING を戻すときも再試行回数を増やす。
16. **点数と manual_score（§13, §31）**: LLM の score は整数に限る。manual_score は 0 以上で配点以下の数値だけを有効とし、不正な入力は無視して Control に理由を出す。
17. **未実装の提供元（§30）**: LLM の問題があるのに、実装済みでない提供元（現在は ANTHROPIC 以外）を選ぶと検証エラーにする。
18. **question_id の書式**: Questions の question_id 列は文字列の書式にし、「001」が数値にならないようにする。

19. **先生が触るシート（§6, §7, ADR 0007）**: 先頭に「試験作成」と「結果」の2枚を置き、設計書 §6 の8シートは裏方として隠す。「これでOK」は試験作成!B2（Control!B2 も引き続き使える）。状態・メッセージ・フォームURL・合計点は両方に出る。結果シートは Results から数式で引く表示専用のシート。メニュー名は「採点を今すぐ進める」「手動採点を反映」に変えた。

20. **多言語の回答（§10, §38, ADR 0008）**: 正規化は NFKC に加え、全言語の大文字小文字をそろえ、ラテン文字のアクセントを外す（日本語の濁点は外さない）。数値は各国の十進数字を読み、「3,14」は小数とみなす。短答で正答と一致しない回答のうち、正答・別解に無い種類の文字で書かれたものと、数値で数として読めず日本語以外の文字で書かれたものだけ、REVIEW_REQUIRED にして Claude が意味で判定する。それ以外の誤答は0点で確定する。
21. **氏名欄（§17, ADR 0013）**: フォームの先頭に必須の「氏名（Name）」を自動で入れる。FormMapping には問題番号 `__NAME__` で記録する。氏名欄そのものは採点しない（Results の行にならない）が、配点を満点にして、フォームの合計点と講評の受け皿にする（補足28）。Results の末尾に `respondent_name` 列を足す（列の増加は利用者の依頼による）。
22. **1人1回（§17）**: 既定でフォームの回答を1人1回に制限する（`setLimitOneResponsePerUser`）。学生は Google ログインが必要。Settings の `LIMIT_ONE_RESPONSE` を FALSE にすると外せる。

23. **種類「説明」（ADR 0007 の追加）**: 試験作成の種類に「説明」を足す。裏方では `question_type=INFO`・`grading_mode=NONE`。フォームでは答えのない見出し＋説明の項目になり、FormMapping に記録せず採点しない。`NONE` は INFO でだけ使える。
24. **加点なしの欄**: 配点0の記述は、採点時に状態 `NO_POINTS`（0点で確定）にし、手動採点を待たない。
25. **クラス欄（§17）**: 名簿シートにクラスがあれば、氏名欄の次に必須の選択式「クラス（Class）」を出す。FormMapping には `__CLASS__` で記録し、採点しない。Results の末尾に `respondent_class` 列を足す（列の増加は利用者の依頼による）。
26. **受付ページ（ADR 0009）**: 名簿・資料・割り当てのシートを足す（利用者の依頼による）。受付ページは別の Apps Script プロジェクト（`reception/`）で、作成者として実行・誰でも開ける。資料番号は資料を受け取った順の通し番号で、同じクラス・氏名は同じ番号。
27. **アカウントの収集（§16, §17）**: `COLLECT_EMAIL` の初期値を TRUE にする（利用者の依頼による）。結果を Classroom の受講者アカウントへ返すとき、回答者を照合するため。値は Results の既存の `respondent_email` 列に入る（列は増やさない）。学生が Classroom と別のアカウントでログインすると照合できないので、運用で Classroom のアカウントを使うよう案内する。既にある Settings シートの値は書き換えない。
28. **合計点だけのフォーム（§17, §27, ADR 0013）**: 新しく作るフォームでは、問題の項目に点数を付けず、選択肢の正解も設定しない（選択式も仕組みの中で採点する）。問題の項目に正解・不正解のフィードバックも付けない（正解を設定しないので、付けると全員に不正解のほうが出る。講評は氏名欄に一本化する）。Questions の `feedback_correct`・`feedback_incorrect` の列は残すが、フォームには使わない。氏名欄の配点を満点（掲載した問題の配点の合計）にする。配点が変われば定義の指紋も変わり、同期または新しい版で満点が直る。確定した回答の書き戻しでは、問題の項目には書かず、氏名欄に `setScore(合計点)` と `setFeedback(講評)` だけを書く。合計点は Results の最終点の和（`__LATE__` の行を含む）。既に回答があるフォームを、この形に作り直すことはしない。
29. **講評（ADR 0011, 0013）**: 講評は回答の各行から純粋関数で組み立てる。問題ごとに「問題文の1行目：最終点 / 満点点」と採点の理由（grading_reason。空なら省く）を並べる。氏名欄・クラス欄・加点なしの欄（`NO_POINTS`）は出さない。`__LATE__` の行は内訳に出さず、最終点が負のときだけ、最後に書き添える。manual_score が空（自動で抑えた）なら「授業時間外の提出のため、合計点は上限の○点までです」（○は上限点。`__LATE__` の行の問題文「授業時間外の提出（上限○点）」から読むか、呼び出し側から渡す）、先生が manual_score で決めたなら「授業時間外の提出のため、合計点は○点です」（○は抑えた後の合計点）。
30. **回答の概要の非表示（ADR 0011）**: 他の学生の回答が見えないよう、フォームの作成・同期のたびに（定義が同じで何もしないときも）`setPublishingSummary(false)` にする。
31. **成績の公開の案内（ADR 0013）**: 成績の公開の設定（送信直後／後で手動）は Apps Script から変えられない。新しいフォーム、または新しい版を作ったときは、メッセージに「フォームの設定で、成績の公開を『後で手動で公開』にしてください」を出す。
32. **授業外の上限点と `__LATE__` の行（ADR 0013）**: 試験作成シートの上部の E・F 列に「授業外の上限点」（F1）と、クラスごとの「授業の終わる日時」の表（3行目が見出し、4〜9行目）を置く。クラスは初期セットアップと「これでOK」のたびに名簿のクラスの順に並べ直し、先生が入れた日時はクラスについたまま残す（名簿から消えたクラスも日時があれば後ろに残す）。「これでOK」のとき Settings の `LATE_CAP` と `CLASS_END_<クラス>` の行へ写す（行を足すだけで列は変えない）。フォームには出ないので定義の指紋に入らず、フォームの作り直しは起きない。上限点が数でなければ「これでOK」はエラーにする。「手動採点を反映」も、最初に試験作成シートの上限点と終わる日時を Settings へ写す（「これでOK」を押さずに直しても新しい値で決め直す。フォームは作り直さない）。上限点が数でなければ、「これでOK」と同じ理由をメッセージに出して何もせずに止まる。
    - `__LATE__` の行は純粋関数（`src/LateCap.js` の `planLateRow`）が決める。合計点は `__LATE__` を除く最終点の和。上限点が空欄・合計が上限以下・授業内（送信日時が終わる日時以前）なら行なし。合計が上限を超えるとき、名簿で氏名（集計表の照合と同じく、NFKC・大文字小文字をそろえ、前後の空白を除き連続する空白を1つにする）から引いたクラスが見つからない（別々のクラスに同じ氏名がある場合を含む）、学生が選んだクラスと違う、そのクラスの終わる日時が空欄なら、`REVIEW_REQUIRED`（final_score は空、grading_mode は MANUAL）にする。授業外なら final_score を「上限点 − 合計点」、状態を `AUTO_GRADED`（grading_mode は AUTO、auto_score も同じ値）にする。max_score は 0、問題文は「授業時間外の提出（上限○点）」。
    - 合計が上限以下なら、授業内か授業外かを決める必要がないので、名簿で見つからなくても要確認にしない。
    - `__LATE__` の manual_score は「-(`__LATE__` を除く合計点) ≤ n ≤ 0」の数だけを有効とする（0 なら抑えない。正の数は加点になり、合計点より多く抑えると合計が負になるので、範囲外は無視して理由を出す）。manual_score が入った `__LATE__` の行は先生の判断として残し、状態を `MANUAL_GRADED` にする。
    - 上限の計画は、定期処理で結果を書く時点（`runJob_`）と「手動採点を反映」の両方で毎回やり直し、不要になった行は消す。回答の確定の判定には `__LATE__` の行も含める（要確認が残れば確定しない）。「手動採点を反映」の新旧の比べ方は問題番号で行い、確定済みの回答でも上限が変われば合計点を書き戻し直す。決め直して要確認に戻った回答は、Queue も `COMPLETED` から `REVIEW_REQUIRED` に戻す（集計表が確定とみなさないため）。このとき Logs に WARN「この回答のフォームの点数は、確定し直すまで古いままです」を出す（フォームに書き戻した点は消せないため）。

33. **保管の印（ADR 0010）**: 集計表の「保管する」は、テストの Settings に `ARCHIVED` の行（値 TRUE）を足す。`ARCHIVED` が TRUE のとき、1分ごとの処理はフォームの新しい回答を取り込まない（フォームは集計表が閉じている）。待ち行列に未完了の仕事（`PENDING`・`RETRY`・`PROCESSING`）が残っていれば、いつもどおり採点を続ける。残っていなければ、このプロジェクトのトリガーをすべて外し、Settings に `TRIGGERS_REMOVED` の行（値は日時）を書いて終わる。`REVIEW_REQUIRED` は「手動採点を反映」を待つだけで、`FAILED` はもう処理しないので、未完了に数えない（確定していない回答が残るテストは、集計表の側で保管を止める）。「これでOK」（試験作成!B2 と Control!B2）は `ARCHIVED` なら何もせず、メッセージに「このテストは保管済みです」と出す。どちらも Settings に行を足すだけで、列は変えない。
34. **初期セットアップの掃除（ADR 0010）**: ひな型や別のテストをコピーすると、Document Properties の現在のフォームの記録（補足13）が写ることがある。初期セットアップは、記録のフォーム ID がこのスプレッドシートの FormMapping に無ければ、フォーム ID・版・定義の指紋をまとめて消す（コピー元のフォームを書き換えたり、その回答を取り込んだりしないため）。FormMapping にあれば消さない。

## 既知の制約

- 採点は「現在の Questions」を使う。correct_answer・auto_rule・ルーブリックはフォームの定義ハッシュに入らないため、回答が残っている版の採点が終わる前に変更しない。
- 1分ごとのトリガーは、試験時間外も動く。Apps Script のトリガー実行時間の1日の上限に収まるか、実環境で確かめる。
- 旧版の作成中に失敗すると、旧フォームだけが閉じた状態になりうる。Control の MESSAGE に出るので、導入担当者が確認する。

## 実環境で確認が要る項目（【未確認】）

- 成績の公開タイミング（送信直後か後か）を Apps Script から設定できるか。できなければ運用で補う。
- Apps Script の実行時間・UrlFetch の1日の上限が60人規模で足りるか。
- `setCollectEmail(true)` で、学生にログインが必ず求められ、確かめ済みのアカウントが入るか（自分で打ち込む形にならないか）。
- 回答先のスプレッドシートに版ごとに増える「フォームの回答 N」シートの扱い。
- `LLM_CONFIDENCE_THRESHOLD` 0.80 での要確認の出方（実際の答案で確かめる）。
